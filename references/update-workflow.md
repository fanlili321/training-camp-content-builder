# 更新模式：在已有训练营文档上改

适用于：换主推产品（如「投顾第一课」从主动优选版本改成指数增强版本）、复用另一期训练营的内容、更新数据、换图。

与新建模式的区别：**不出大纲**，以现有文档为底稿；交付物是一份修改清单和改好的文档。写作格式、合规、复核清单、飞书读写规范照常使用。

## 1. 读取与比对

1. 读取目标文档（带 block ID）和可见评论，在本地存一份改前快照，记录 revision_id。
2. **找到同一课程的其他版本，逐行比对**（如主动优选版、365版、指数增强版）。比对结果会告诉你哪些地方是各版本通用的，哪些地方随版本变化。只改随版本变化的地方，通用部分不动。
   - 投顾第一课的经验：第1-3天基本通用，随版本变化的是：
     - 第2天：跟车、分散配置、投顾费里“以XX组合为例”的举例
     - 第3天：几个组合的介绍顺序、逆势投资数据、持有人收益图和配文
     - 第4天：整天围绕主推组合，要整体替换
3. 要复用别的训练营内容时，**读飞书上的最新版，不用本地快照**。定稿之后常常还会补风险提示、换图。
4. **下载文档里的全部图片逐张看**（可先拼成缩略图总览，再放大细看），找出：
   - 图里写着旧产品名称或数据的
   - 图里文字不适用于新产品的（例：主动优选的调仓图写着“基金经理离职”，不适合指增）
   - 图和正文对不上的（例：正文写“2025年突破13000只”，图是“截至2026年4月，14029只”）

## 2. 出修改清单，停下来等确认

清单落在本地 md 文件，按天分组，列：`序号 | 位置 | 原文 | 建议改为 | 依据`。另列：

- **通读发现的其他问题**：原版本就有的错误、病句、过时的时点说法、格式问题。
- **需要用户定的问题**：只列答案会明显改变改法的。常见的有：
  - 数据用哪个日期口径
  - 以谁的名义开营
  - 旧产品的图删还是留
- **图片汇总**：每张要动的图写清删除、换成哪张、调整顺序。

数据和口径：

- **同一个指标，全文只用一个日期口径。** 发现两处日期不同（例：第3天持有人图截至6月30日写7.87%，第4天新数据截至11月13日写19.92%），在清单里指出，让用户选定统一用哪个，或删掉其中一处。
- 复用的数据和源训练营保持一致；源里没有的数据（如盈利比例、策略超额）不写，也不留占位。

用户明确答复“全采纳”或指出具体条目后才动手。只回答了问题、没确认清单时，先复述要改哪些，再等确认。

## 3. 改写

1. 写入前重新读取文档。用户可能在中间自己改过（例：把日期改到11月、星级改成5星左右），不要用旧内容覆盖。
2. 行内换词用 `str_replace`，pattern 要在全文唯一；整段替换用 `block_replace` 指定起止 block。
3. **整段替换前，先列出范围内的所有图片，逐张决定去留。** 曾在重写第4天时把本该保留的逆势投资申购图一起删了，回读时才发现补回。
4. 从别的飞书文档复用图片，可直接写 `<img src="原图token"/>`。写入后图片会被重命名、转格式，要下载回来确认是哪张图、分辨率够不够。本地新做的图用 `<img path="@./文件名"/>` 上传。
5. 复用内容时保留源稿里的风险提示原句；新加的业绩、持有人收益数据旁边就近补风险提示。
6. 替换带评论的图片块后，评论不会自动关闭；留给评论人确认后关闭，不代为标记已解决。

## 4. 回读核对

- 重新读取全文，和改前快照逐行比对，确认清单每一条都落地、没有误改相邻段落。
- 搜索旧产品名，逐条确认剩下的都是合理保留（如同时提到多个组合的句子）。
- 用脚本检查每张图前后都有 `★ ★ ★ ★ ★`；脚本往往比人工列的发现得更多。
- 统计图片数，和“改前数量 − 删除 + 新增”对得上。
- 在清单文件末尾追加执行记录：改了哪些、清单以外多做了什么、发送前还要复核什么（星级、时点说法、到期的优惠）。

## 5. 指代不清时

用户说“第X页”“那张图”而文档里对不上时，先自己核对（导出PDF看页码、查评论锚点），仍然对不上就直接问，不要先动手改。
